Implement a record store in store/store.odin. store_init takes a capacity in bytes and reserves all the memory it will ever use up front from the given allocator. store_add copies the data in and returns an Id (ok is false when it cannot fit). store_get returns the stored bytes for a live Id, store_remove frees a record for reuse and returns false for an unknown Id, and store_destroy releases everything. Records are 16 to 4096 bytes and are added and removed in random order for a long time. store_add must keep succeeding whenever the live bytes are at most 75 percent of the capacity, so fragmentation must stay low, and the store must not make a heap allocation per record. Make `odin test store` pass and keep the driver in drive/ working. Work only inside the current directory.
